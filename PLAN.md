
Ниже — **план на ~2 дня**: не «идеальный продукт», а **проходимый минимум по обязателькам + сдача**, чтобы жюри могло проверить.

## День 0 (2–4 часа, до кодинга)

1. **Зафиксировать scope одной фразой:** «Редактор страницы + вставка таблицы из Fusion + автосейв + slash + хоткеи + ссылки/backlinks + один сценарий коллаба». Всё остальное — только если останется время.
2. **Прочитать** `docs/WikiLive_features.md` и **отметить галочками** что уже есть / что нет.
3. **Fusion:** один рабочий поток: токен в `.env`, один запрос «список/запись» — чтобы не тонуть в API в последний час.
4. **Решить коллаб:** самый быстрый проверяемый вариант — **два браузера / два пользователя**, одна сущность страницы (CRDT/операционные трансформы не обязательны для «проверяемого» — часто достаточно **последняя запись wins + видимые изменения** или **Giper Baza**, если уже поднято как в blitz). Не расползайтесь в «идеальный OT».

## День 1 — «обязаловка работает в демо»

| Блок | Делать так |
|------|------------|
| **Страница** | Одна модель контента (JSON/markdown-блоки), одна страница в UI — не расползаться на вики из 50 страниц. |
| **Редактор** | Взять **готовый** open-source (TipTap/ProseMirror/Lexical и т.д.) — не писать редактор с нуля. |
| **Вставка таблицы** | Минимум: **embed по id** из Fusion + **iframe/виджет/встроенный фрагмент UI**, чтобы было видно «таблица **внутри** страницы», не просто URL в тексте. |
| **Автосейв + кэш** | `localStorage` + дебаунс + периодический `fetch` на бэкенд/Fusion. После F5 — **восстановление из localStorage**. |
| **Slash-menu** | 2–3 пункта: параграф, заголовок, **вставить таблицу** — достаточно для чек-листа. |
| **Хоткеи** | Задокументировать в **README** 3–5 штук (открыть slash, жирный, и т.д.) — по PRD перечень в README важен. |

**К вечеру дня 1:** сценарий «открыл → поправил текст → вставил таблицу → перезагрузил → текст на месте».

## День 2 — «ссылки, коллаб, упаковка»

| Блок | Делать так |
|------|------------|
| **Ссылки + backlinks** | Минимум: синтаксис `[[page-id]]` или выбор из 3–5 заглушек-страниц; **backlinks** — простая индексация: при сохранении парсить ссылки и показать блок «на эту страницу ссылаются: …». Не делать полнотекстовый поиск по вики. |
| **Коллаб** | Один **заранее записанный** сценарий в демо: два окна, оба видят обновление после сохранения/синка (или CRDT-событие). 2 минуты видео — достаточно. |
| **Схема** | Одна картинка: «Клиент → Fusion API → …» — в Figma/excalidraw за 30 минут. |
| **Шаблон фич** | Заполнить `docs/WikiLive_features.md` честно: что сделано, как проверить (1 строка на фичу). |
| **Запуск** | `docker-compose` или **одна команда** из README; если Docker не взлетит — **жёстко** описать `npm i && …` и зафиксировать версию Node. |
| **Видео 3–5 мин** | Сценарий: создать страницу → slash → таблица → ссылка → backlinks → перезагрузка → второй пользователь/вкладка. |
| **Слайды** | 5–7 слайдов: проблема → решение → обязаловка по пунктам → демо → что дальше. |

## Что сознательно отложить (если только 2 дня)

- AI, граф связей, комменты, версии, плагины, pixel-perfect Design Kit — **только** если обязаловка закрыта и видео/репо готовы.
- «Живая» двусторонняя синхронизация таблицы с Fusion — **доп. фича**; для минимума хватит **встраивания** и стабильного API-чтения.

## Критерий «мы успели»

К концу второго дня у вас есть: **репо + README с хоткеями + заполненный шаблон фич + короткое видео + схема + слайды**, и по **каждой** обязательной строке из PRD есть **30 секунд в видео**, где это видно.

Такой план режет всё лишнее и направляет время в то, за что реально ставят баллы и без чего решение не допускают к проверке.
